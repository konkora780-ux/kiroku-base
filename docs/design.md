## 0．置き場所と、家計簿アプリとの関係

- 記録ベースは **`~/Developer/kiroku-base`（このフォルダ）** で作る。
- `~/Developer/my-app` は家計簿アプリ（保留中）。記録ベースとは**コードも資料も共有しない**。
  - 企画書は `my-app/kiroku-base-proposal.md` から `docs/proposal.md` へ**コピー**した（元のファイルはそのまま残してある）。
- 他の「〇〇-base」アプリ（練習ベースなど）と同じ作り方にそろえる（→「7．技術構成」）。

## 1．全体の考え方

1. **毎時間の記録は「開く → つぎの記録をつくる → 書く」の3手で始められる。**
2. **書いたものは消えない。** 1文字ごとに端末へ自動保存し、削除も「ごみ箱」を経由する。
3. **「書く」と「配置を変える」を別の画面に分ける。** 書いているときに欄が動くことはない。
4. **シートは画面でも印刷でも同じ大きさ（210mm×297mm）で作る。** 見たままが印刷される。
5. **iPad 1台の中だけで完結する。** 記録はそのiPadの中にだけ保存し、外のサービス（クラウド・サーバー）には送らない。インターネットが必要なのは、最初にアプリを入れるときと、アプリを更新するときだけ。
6. **児童生徒の名前はシートにもアプリにも書かない。** 一人一台なので、どのiPadが誰のものかで区別する。

## 2．画面構成と移動

```text
                 ┌────────────┐
                 │  ホーム       │  単元（記録ブック）の一覧
                 └─────┬──────┘
         「新しい単元」 │        単元をタップ
        ┌──────────────┴───────────────┐
        ▼                                  ▼
 ┌────────────┐                   ┌──────────────┐
 │ ①項目選択     │                   │ 単元の記録一覧   │  ページの一覧（日付・タイトル・写真）
 └─────┬──────┘                   └──┬───┬────┬───┘
        ▼                              │      │       │
 ┌────────────┐   「様式を変える」     │      │       │
 │ ②様式調整     │◀──────────────────┘      │       │
 └─────┬──────┘                              │       │
        │「この様式で始める」                    │       │
        ▼              「つぎの記録をつくる」    │       │「ふりかえる」
 ┌────────────┐◀───────────────────────┘       ▼
 │ 記録入力       │◀─「このページに書き足す」──┌──────────┐
 └─────┬──────┘                              │ 振り返り    │ 左右にめくる
        │「印刷」                                └────┬─────┘
        ▼                                              │「印刷」
 ┌────────────┐◀──────────────────────────────┘
 │ 印刷プレビュー │  一枚だけ。印刷／PDFで保存
 └────────────┘
```

| 画面 | 主なボタン（大きく表示） | 役割 |
|---|---|---|
| ホーム | 単元のカード（表紙写真＋単元名＋枚数）、「＋ 新しい単元」 | 最近使った単元が上。終わった単元も残る |
| 単元の記録一覧 | **「つぎの記録をつくる」**（いちばん大きい）、「ふりかえる」、各ページのカード | ページのカードを押すと、そのページを開く |
| ①項目選択 | 項目のカード（押すとチェック）、「つぎへ」 | シートに載せる欄を選ぶ |
| ②様式調整 | A4の見本、欄を動かす・大きさを変える、「この様式で始める」 | 先生と一緒に行う想定 |
| 記録入力 | 欄をタップ → 大きな入力画面、「もどす」、保存の表示 | 欄の位置は動かない |
| 振り返り | 左右スワイプ／「←」「→」、「このページに書き足す」 | 1ページずつ全体を表示 |
| 印刷プレビュー | 「印刷する」、「PDFで保存」 | 印刷されるそのままを表示 |

### 3つの操作のちがい（取り違えないように）

| 操作 | どこにあるか | 何が起きるか | 見た目 |
|---|---|---|---|
| **つぎの記録をつくる** | 単元の記録一覧のいちばん上 | 新しいページが1枚ふえる | 緑の大きいボタン＋「＋」 |
| **このページに書き足す** | 開いたページ・振り返り中のページ | そのページを書きかえる（ページはふえない） | えんぴつの絵＋ページ番号を表示「3まいめに書き足す」 |
| **ふりかえる** | 単元の記録一覧 | 見るだけ。書きかえはできない | 本の絵 |

## 3．操作の例

### 児童生徒：同じ単元の次の授業（毎時間の流れ）

1. ホームで「トマトを育てよう」を押す。
2. 「つぎの記録をつくる」を押す。
3. 「前回の目標を使う？」と出る → 「使う」「使わない」を押す（目標と次回に向けてだけ。写真・感想は引き継がない）。
4. 日付は今日が自動で入る。タイトルの欄を押して書く。
5. 写真の欄を押す →「カメラでとる」で撮影。
6. 感想の欄を押す →「楽しかった」「自分でできた」などを押す。必要なら文も書く。
7. 画面の上に「保存しました ✓」が出ている。そのままホームに戻ってよい（「保存」ボタンは押さなくてよい）。

### 先生：新しい単元の準備（児童生徒と一緒に）

1. ホームで「＋ 新しい単元」→ 単元名「卓上織り機で作品を作ろう」を入力。
2. 項目を選ぶ（例：日付・タイトル・今日の目標・写真・取り組んだこと・感想・先生の補足）。
3. 「つぎへ」→ A4に自動で並ぶ。写真を大きくしたい場合は、写真の欄の角をつまんで広げる。
4. 「この様式で始める」→ そのまま1時間目の記録入力へ。

### 先生：補足を書く

1. 画面右上の「先生」ボタンを長押し（約1秒）して先生モードにする。
2. 「先生より」の欄が書けるようになる。先生モード中は画面の枠の色が変わる。

## 4．A4縦の記録シート

見本：[sheet-sample.html](sheet-sample.html)（ブラウザで開く。そのまま印刷するとA4一枚）

- 一番上は固定の帯：**単元名・何まいめ**（自動で入る。項目選択には出さない）。**名前の欄は作らない。**
- その下を **6列×12段のます目** に分け、各欄は「左から何列・上から何段・幅・高さ」で置く。
  - 自由な位置（ピクセル単位）ではなく、ます目に吸いつく方式にする。iPadの指操作でもそろえやすく、印刷でもずれない。
- 本人の欄は緑の見出し、**先生の補足は青い枠と薄い青の背景**で区別する。
- 文字の大きさは欄ごとに「大・中・小」の3段階から選ぶ。**自動で小さくはしない。**
- 書いた文が欄に入りきらないときは、欄の枠を赤くし「入りきりません（あと◯行くらい）」と出す。直し方は「文を短くする」「欄を大きくする」「文字を小さくする（3段階の範囲で）」。

### 項目を選んだ直後の自動配置（はじめの並べ方）

選んだ項目を下の順番で、上から詰めて置く。

| 順 | 項目 | はじめの大きさ（幅×高さ） |
|---|---|---|
| 1 | 日付 | 2×1 |
| 2 | タイトル | 残りの幅×1 |
| 3 | 今日の目標 | 6×1 |
| 4 | 写真 | 4×4（文章の欄が1つ以上あれば右に2×4を並べる） |
| 5〜 | 取り組んだこと／成果・できたこと／成長・変化／次回に向けて／自由記入 | 3×2 を2つずつ横に並べる |
| — | 感想 | 6×2（選択肢があるので広め） |
| 最後 | 教師の補足 | 3×2（右下） |

12段に収まらない場合は、文章の欄の高さを2→1に縮めて収める。それでも無理なら「項目が多すぎます」と表示して減らしてもらう。

## 5．項目選択・配置調整・入力の操作

### ①項目選択

- 11項目をカード（絵＋名前）で並べる。押すとチェックが付く。
- よく使う組み合わせを「おすすめ」として最初からチェックしておく：日付・タイトル・今日の目標・写真・取り組んだこと・感想・次回に向けて。
- 写真の欄は「写真の数（1枚／2枚）」を選べる。
- 感想の欄には選択肢（「楽しかった」「難しかった」「またやりたい」「自分でできた」「手伝ってもらってできた」）が付く。初期版は固定。

### ②様式調整（配置を変える画面）

- A4の見本を画面いっぱいに出す。中身は入っていない（見出しだけ）。
- 欄を**長押ししてから**動かす（ふつうのタップでは動かない）。右下の丸いつまみで大きさを変える。
- 指で動かすのが難しい人向けに、欄を選んで「↑↓←→」「広げる・せばめる」ボタンでも動かせる。
- 欄の追加・削除もここで行う。削除しても、すでに書いたページの中身は消えない。
- 「この単元のこれからのページに使う」（基本様式の変更）と「このページだけ変える」を分けて選ぶ。

### 記録入力

- シート全体を表示し、欄をタップすると**入力画面が大きく開く**（画面の8割くらい）。
  - 文章：大きな文字の入力欄。iPadのキーボード・音声入力（iPad標準のもの）がそのまま使える。
  - 選択肢：大きなボタンを押して選ぶ。もう一度押すと外れる。
  - 写真：「カメラでとる」「写真をえらぶ」の2つのボタン。撮った写真は自動で小さくして保存する。
- 「もどす」ボタン：直前の変更を取り消す（その画面を開いている間、20回までさかのぼれる）。
- 画面の上に保存の状態を常に表示：「保存中…」→「保存しました ✓」。

### 振り返り

- 1ページずつ、シートの全体を表示。左右にスワイプ、または大きな「←」「→」でめくる。
- 下にページの小さな一覧（写真のサムネイル）を出し、押すとそのページへ飛ぶ。
- 振り返り中は書きかえられない。書きたいときは「このページに書き足す」を押す。

## 6．データの形

```text
book（単元の記録ブック）
  id, title, createdAt, updatedAt, deletedAt?
  template: レイアウト（基本様式）       ← これからのページ用
  coverPhotoId?                          ← ホームに出す表紙写真

sheet（授業ごとの記録シート）
  id, bookId, no（何まいめ）, createdAt, updatedAt, deletedAt?
  layout: レイアウト（作ったときの基本様式の写し）  ← このページ専用。基本様式を変えても変わらない
  values: { 欄のid: 中身 }

レイアウト = { blocks: [ { id, kind, label, x, y, w, h, size: 's'|'m'|'l', options } ] }
  kind = date | title | goal | photo | did | result | growth | feeling | next | free | teacher
  x, y, w, h = 6列×12段のます目での位置と大きさ

中身（values の1つ分）
  { text: '...', choices: ['楽しかった', ...], photoIds: ['...'] }

photo（写真）
  id, sheetId, blob（長い辺1600px程度のJPEG）, thumb（一覧用の小さい画像）, width, height, createdAt

meta（設定）
  version, teacherModeSetting など（名前は持たない）
```

ポイント：

- **ページは自分専用のレイアウトを持つ。** 基本様式を変えても過去のページは変わらない（要件7）。
- 欄を削除しても、そのページの `values` は消さずに残す（あとで戻せる）。
- 写真は `values` の中に埋めこまず、別の場所に置く。ページの保存が軽くなり、写真だけを書き出すのも楽になる。
- 削除は `deletedAt` を付けるだけ（ごみ箱）。ごみ箱から戻せる。本当に消すのは「ごみ箱を空にする」を押したときだけ。

## 7．技術構成と選んだ理由

| 部分 | 使うもの | 理由 |
|---|---|---|
| アプリの形 | **Webアプリ（PWA）を iPad のホーム画面に追加して使う** | App Store への登録が不要。学校のiPadでもSafariがあれば使える。他の「〇〇-base」と同じ |
| 画面 | HTML・CSS・JavaScript（ライブラリなし、ビルド不要） | 練習ベース等と同じ作り。ClaudeでもCodexでも引き継ぎやすい |
| 端末内の保存 | **IndexedDB**（ブラウザの中のデータベース） | 写真もそのまま入る。通信がなくても読み書きできる |
| 通信なしで開く | Service Worker（sw.js：アプリ本体の控えを端末に置く） | 電波がなくてもアプリが開く |
| 印刷・PDF | 210mm×297mm で作ったシートを、iPad の印刷機能で出す | AirPrint で印刷。印刷画面から「PDFとして保存」もできる |
| アプリの配布元 | GitHub Pages（他のアプリと同じ） | 最初に1回開いてホーム画面に追加するための置き場所。無料。置くのは**アプリの仕組みだけ**で、記録の中身は送られない。追加した後は通信なしで動く |

### iPad で記録を失わないための注意（重要）

1. **必ず「ホーム画面に追加」したアイコンから開く。**
   - iPad の Safari では、Safariで開いたときとホーム画面のアイコンから開いたときで、**保存場所が別々**になる。片方で書いた記録は、もう片方には出ない。
   - Safari で開いたままのサイトは、しばらく使わないと保存データが消されることがある。ホーム画面のアイコンから開くアプリは、この対象外。
   - アプリ側でも、Safariで開かれたら「ホーム画面に追加してから使ってください」と案内を出す。
2. 起動時に「このデータを消さないで」とブラウザに申し出る機能（`navigator.storage.persist()`）を使う。
3. 次のことをすると、記録はiPadから消える（元に戻す方法はない）。運用で避ける（→ 8）。
   - ホーム画面から記録ベースのアイコンを削除する
   - iPadを初期化する（年度末の入れ替え・修理・交換など）
   - iPadの設定から、記録ベースのWebサイトのデータを消す

## 8．保存・オフライン・見せ方（iPadの中だけで完結）

### 端末内保存

- 文字を打つたびに、0.5秒後に自動保存。アプリを閉じる瞬間・別のアプリに切り替わる瞬間にも保存。
- 保存の状態を画面上部に表示：「保存中…」「保存しました ✓」「保存できませんでした（もう一度）」。
- 写真は撮った直後にiPadへ保存してから画面に出す（画面に出たのに保存されていない、を防ぐ）。
- 記録の作成・保存・振り返り・印刷に通信は使わない。通信が切れても何も変わらない。
- 「同期待ち」の状態はない（外へ送らないため）。

### バックアップ

- **初期版では作らない**（ご希望により）。記録はそのiPadの中だけにある。
- そのかわり、消える原因（→ 7の注意3）を減らす：
  - 起動時に「このデータを消さないで」とブラウザに申し出る（`navigator.storage.persist()`）。
  - ページや単元の削除は、ごみ箱を経由する。
  - 設定画面に「アイコンを消すと記録も消えます」と一言書いておく。
- 年度末の入れ替えなどで残したい記録は、**シートを印刷・PDF保存して残す**（これは今の機能でできる）。

### 見せ方（共有のかわり）

- 外部への共有リンクは作らない。見たい人には、
  - **そのiPadの「振り返り」画面を見せる**、または
  - **シートを印刷する／PDFにする**。

## 13．追加した機能（2026-10-14）

### 「今日の目標」の書き方（先生が様式で決める）

- 先生モードの「様式を変える」で「今日の目標」の欄をえらぶと、書き方を **文字／数字／文字＋数字** から選べる。
- 数字のときは単位（回・まい・こ・分・秒・cm・m・ページ、または自由に入力）を決める。
- **できた数の欄**（あり／なし）：「🎯 目標 10回　できた 8回」と並べて記録する。
- 児童生徒は大きな「−」「＋」ボタンか数字キーで数を入れる。
- 「つぎの記録をつくる」では、目標の文と数を引き継げる（できた数は引き継がない）。

### 目標の候補

- 先生が単元ごとに目標の候補を登録する（単元の画面の「🎯 目標の候補」、または様式の画面）。
- 児童生徒は目標を書くとき、候補を押して選べる。自分で書くこともできる。
- 候補は単元（`book.goalChoices`）に保存。

### 数の記録（項目「🔢 数の記録」）

- 例：葉の数（まい）、黄色い実の数（こ）、赤い実の数（こ）、緑の実の数（こ）。
- 数える項目は先生が様式の画面で足す・並べかえる・消す（`block.rows = [{id, label, unit}]`）。
- 児童生徒は項目ごとに数を入れる。入力のとき、**前回のページの数**（「前回 6まい」）を横に表示する。
- 値は `values[欄id].nums = { 項目id: 数 }`。
- ページの一覧のカードに、目標と数の記録を1行で表示する。

### データの追加

- 目標の欄：`goalMode`（text|number|both）、`unit`、`showResult`。値は `{ text, num, result }`
- 数の記録の欄：`rows`。値は `{ nums }`
- 単元：`goalChoices`（目標の候補の文字列の配列）

## 14．評価を受けての改善（2026-10-14）

評価（`docs/codex-review-2026-10-14.md`）の指摘1〜4と、使いやすさの案の一部を反映した。

### 保存（`js/saver.js`）

- 書いたら0.15秒以内に保存する（以前は0.5秒待っていた）。
- 変更ごとに番号を進め、最新の番号まで保存できたかで「保存済み」を判断する。保存は同時に1つだけ。
- 保存に失敗したら画面を移らず、「保存できませんでした」と出す（この画面にのこる／保存せずに移る／もう一度）。3秒ごとに自動でも再試行する。
- 画面を離れた後の古い画面は、何も書きこまない（新しい記録を上書きしない）。
- 写真の保存中は、終わるまで画面を移らない。
- 様式の画面にも保存の表示を出し、失敗を知らせる。目標の候補・新しい単元・新しいページの保存失敗も知らせる。

### 写真

- 入力画面を離れて保存できた後、そのページで使っていない写真（外した・入れかえた写真）を消す。
- 表示用のデータ（URL）は、画面を移るたびに手放す。
- 写真がいっぱい（2まい）のときは、どの写真と入れかえるか選ぶ。1まいのときはそのまま入れかわる（「もどす」で前の写真にもどせる）。

### 細かい直し

- 様式の画面の「null null」の表示を直した（子要素の入れかえは `fill()` を使う）。
- 「もどす」：変更する前の中身を積むようにし、1回目から前にもどるようにした。
- 印刷前の注意に「入力にもどる」「配置を直す」（先生モード）を付けた。

### 様式

- **新しい単元で、前に作った単元の様式をコピーできる**（項目・配置・目標の書き方・数える項目・目標の候補。記録の中身はコピーしない）。
- **先生モードで「つぎの記録をつくる」を押すと、「今の様式でつくる／様式を変えてからつくる」を選べる。** 変えた様式は、そのページから先に使われる（前のページは変わらない）。児童生徒モードでは聞かずにすぐ作る（手順を増やさないため）。
