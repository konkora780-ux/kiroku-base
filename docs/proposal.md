# 記録ベース 企画・設計引き継ぎ書

作成日：2026年10月14日
状態：企画段階。アプリの設計・実装は未着手。
対象：支援学校で使う個人の学習・活動記録アプリ。

## 1．Claude Codeへの依頼

以下をもとに、まず画面構成、操作の流れ、データ構造、保存方式を設計してください。技術構成は未定です。設計案を提示した後、実装へ進める状態を整えてください。

児童生徒の操作の分かりやすさと、入力した記録を失わないことを優先してください。

このフォルダには別の家計簿アプリの資料・コードが存在します。それらを記録ベースの要件として扱わず、既存の資料・コードを上書きしないでください。記録ベースの実装先や既存プロジェクトとの関係は、設計時に整理してください。

## 2．目的

授業や活動について、写真・目標・成果・成長・感想などをA4縦一枚にまとめ、その記録を積み重ねて振り返るアプリです。完成した成果だけでなく、途中の取り組みや変化も記録します。

活動例：トマトの栽培・観察、卓上織り機の制作、作業学習、各教科の授業、継続的な学習。

## 3．ユーザーと合意した基本条件

| 項目 | 要件 |
|---|---|
| 利用環境 | 支援学校。一人一台のiPad |
| 記録の対象 | 個人の活動記録 |
| 入力者 | 児童生徒が中心。教師が必要に応じてサポート |
| 記録のまとまり | 単元ごとの記録ブック |
| シート | A4縦。基本は授業1時間につき一枚 |
| 新しい単元 | 新しい記録ブックを作り、シートの項目・様式を選び直す |
| 過去の記録 | 残し続け、選んで振り返り・追記・編集・続きを記入できる |
| レイアウト | 必要な項目を選んでから、配置や大きさを調整 |
| 振り返り | ページをめくって連続して閲覧 |

| 保存 | 入力した記録を失わず、通信がなくても作業を継続 |

## 4．記録の構造

「個人の記録 → 単元の記録ブック → 授業ごとの記録シート → 写真・文章などの項目」を基本とします。

例：

```text
自分の記録
├─ トマトを育てよう
│  ├─ 1時間目：種まき
│  ├─ 2時間目：発芽の観察
│  └─ 3時間目：葉の数を調べる
└─ 卓上織り機で作品を作ろう
   ├─ 1時間目：糸を選ぶ
   └─ 2時間目：織り始める
```

単元が終了しても記録ブックを残します。後から開き、既存ページへの追記や新しい授業のページ追加ができます。

## 5．基本の操作

### 新しい単元

1. ホームで「新しい単元」を選ぶ。
2. 単元名を入力する。
3. シートに必要な項目をリストから選ぶ。
4. 選んだ項目をA4縦へ自動配置する。
5. 順番・位置・大きさを調整する。
6. 単元の基本様式として保存する。
7. 最初の授業の記録を入力する。

様式の準備は教師が支援できます。

### 同じ単元の次の授業

1. 単元の記録ブックを開く。
2. 「次の記録を作る」を選ぶ。
3. 単元の基本様式で新しいシートを作る。
4. その日の写真・活動・成果・感想を入力する。

前回の写真や感想は自動複製しません。目標などは選択して引き継げる設計が望ましいです。

### 過去の記録

- 「このページに書き足す」：既存シートへの追記・修正。
- 「次の記録を作る」：同じ単元に新しいシートを追加。
- 「振り返る」：保存したシートを順番に閲覧。

これらを明確に区別してください。

## 6．選択できる項目

| 項目 | 内容 |
|---|---|
| 日付 | 授業・活動を行った日 |
| タイトル | その時間の活動名 |
| 今日の目標 | 目指すこと |
| 写真 | 活動中の様子、作品、観察対象 |
| 取り組んだこと | 行った活動や作業 |
| 成果・できたこと | その時間にできたこと |
| 成長・変化 | 以前との違いや上達 |
| 感想 | 本人の感じたこと |
| 次回に向けて | 次に取り組みたいこと |
| 自由記入 | 活動に合わせた記録 |
| 教師の補足 | 支援や観察の記録 |

すべてを必須にせず、必要な項目を選べるようにします。本人の感想と教師の補足は区別して表示します。

「項目を選ぶ」は、まずシートに載せる欄を選ぶ意味です。入力済みの内容を別シートへ転記する高度な機能は、初期版の必須要件ではありません。

## 7．レイアウト

- A4縦の範囲を見ながら調整できる。
- 選択した項目を最初に自動配置する。
- 順番・位置・大きさを調整できる。
- 写真と文章を組み合わせられる。
- 項目を追加・削除できる。
- 同じ単元の次のシートに様式を利用できる。
- 個別シートの変更が過去のシートへ影響しない。
- 単元の基本様式の変更は、以後の新規シートに反映する。

内容がA4に収まらない場合は、はみ出しを示して文章量や配置を調整できるようにします。文字を過度に小さくして自動的に収める方式は避けます。

## 8．入力を支える機能

- 大きなボタンと読みやすい文字。
- 項目を押すと入力欄を大きく開く。
- iPadのカメラから写真を追加。
- 端末内の写真も選択可能。
- 短い文章で記録可能。
- 感想などは選択肢も利用可能。
- 誤操作を元に戻せる。
- 教師が同じ端末で操作を補助できる。

選択肢の例：「楽しかった」「難しかった」「またやりたい」「自分でできた」「手伝ってもらってできた」。選択肢は任意とし、自由に書くこともできます。

手書きや独自の音声入力機能は初期版の必須要件に含めません。

入力と配置調整を操作上区別し、通常の入力中に欄を誤って動かしにくくしてください。

## 10．閲覧・共有の仮案

誰でも閲覧できることはユーザーの希望です。ただし公開方式は未確定です。次は設計用の仮案で、ユーザーが最終決定した内容ではありません。

- 共有リンクを知っている人はログインせず閲覧できる。
- 共有先は閲覧のみ。
- 編集は本人が使う端末で行う。
- 検索エンジンから発見できる一般公開は初期版の要件に含めない。

設計案では、公開する単位と共有操作を示してください。

## 11．保存・オフライン

- 入力内容は端末へ自動保存する。
- 通信がなくても作成・編集・閲覧できる。
- アプリを閉じて再度開いても保存済み記録を復元できる。
- 通信が切れても入力内容を失わない。
- 写真もオフラインで開ける形で保存する。
- 保存中・保存済み・同期待ちを分かりやすく示す。
- 通信が戻った際に共有先へ反映できる方式を検討する。

端末内保存と、端末の故障・紛失に備えるバックアップは別の要件として設計してください。バックアップ先と同期方式は未定です。

## 12．印刷・出力

- 任意の記録シート一枚を選んで印刷できる。
- A4縦で出力する。
- 印刷前にプレビューを確認できる。
- 写真や文章が欠けない。
- シートの配置と印刷結果が対応する。
- 一枚だけのPDF出力も可能にする。

プリンターが利用できなくても、記録の作成・保存は継続できます。
